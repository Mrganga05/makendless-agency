## Intentional motion and state policy

- A never autoplays. Its timer is created only on request, advances twice and stops after the final frame. Changing concepts, hiding the browser document, leaving the viewport or enabling reduced motion stops and cleans it up. A reduced-motion user gets a **Next still** button and discrete, motionless frame changes.
- A source selection also clears tight framing and stops playback, so the source really returns to its original composition. Starting playback from source selects the directed composition.
- C uses one finite mask/opacity reveal on mode change or explicit replay. Its waveform has a single arrival treatment, not a perpetual equalizer. Reduced-motion CSS removes these animations and transitions while retaining all content and state changes.
- Native buttons expose pressed state, labels and focus styles. Links retain their real destinations. No drag-only controls, custom cursor or motion-driven navigation is introduced.
- The two palette candidates use shared theme tokens. Small white labels over the violet artwork have an opaque dark backing, avoiding reliance on the accent color's contrast. The outer gallery uses ink/muted on the shared paper shell, while A/B explicitly use paper text on night. The embedded spatial study gets its own paper panel for its caption and controls. Paper-mode focus uses ink rather than low-contrast aqua. This is an implementation precaution; contrast across every actual rendered overlap still requires review.

## Research applied

Research used primary technical documentation, not imitation of another studio's page layout:

1. [MDN — `clamp()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp). Fluid type needs a bounded minimum and maximum. The prototypes use rem-based bounds with fluid preferred sizes and preserve explicit narrow-screen composition changes. The guide also cautions that text must still scale appropriately at 200%; that browser check remains pending.
2. [MDN — `prefers-reduced-motion`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion). Reduce nonessential movement, particularly large scaling and panning. The shared live preference stops A's playback and changes its control to still stepping; CSS disables the visual transformations' interpolation and mask reveals.
3. [React — `lazy`](https://react.dev/reference/react/lazy). Declare lazy components outside render, provide a Suspense loading state and handle rejected loads with an Error Boundary. B is declared at module scope and has both loading and error content; only the chosen concept mounts.

These readings informed implemented behavior. They do not establish that a visual result is premium, readable on a real device or performant under GPU load.
